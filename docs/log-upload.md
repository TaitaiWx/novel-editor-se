# 日志上传接口约定

关于窗口的「上传日志」按钮，以及崩溃 / 未捕获异常时的自动上传，都会把一个 zip 日志包 POST 到同一个接口。
目前还没有服务端：客户端已经预留了上传逻辑，未配置地址时自动走本地兜底。本文档是给后端实现用的接口约定。

客户端实现：`apps/pc/src/main/log-upload/`（`config.ts` 配置、`bundle.ts` 打包、`uploader.ts` 上传、`service.ts` 兜底、`crash-hooks.ts` 崩溃钩子）。

## 配置上传地址

按优先级：

1. 环境变量 `NOVEL_EDITOR_LOG_UPLOAD_URL`（调试 / 内测包使用）
2. `apps/pc/src/main/log-upload/config.ts` 中的常量 `LOG_UPLOAD_URL`（服务端上线后填写，默认为空）

只接受 `http:` / `https:` 地址，生产环境应使用 https。两者都为空时视为「未配置」。

## 请求

```
POST <LOG_UPLOAD_URL>
Content-Type: application/zip
X-Device-Id: 0f8fad5b-d9cb-469f-a165-70867728950e
X-App-Version: 1.1.0-beta.43
X-Upload-Reason: manual | crash
X-Platform: darwin-arm64
X-Bundle-Sha256: <zip 内容的 SHA-256，十六进制>

<zip 二进制>
```

| 请求头            | 说明                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| `X-Device-Id`     | 设备 ID（`userData/device-id`，随机 UUID，与自动更新请求头一致），用于把多次上传归到同一台设备 |
| `X-App-Version`   | 应用版本号                                                                                     |
| `X-Upload-Reason` | `manual`：用户在关于窗口点击「上传日志」；`crash`：崩溃 / 未捕获异常时自动上传                 |
| `X-Platform`      | `<process.platform>-<process.arch>`                                                            |
| `X-Bundle-Sha256` | 请求体校验值，服务端可据此去重或校验完整性                                                     |

请求体是原始 zip（不是 multipart）。

### 大小限制

- 客户端：单个日志文件只保留末尾 2 MB，所有日志合计不超过 12 MB（未压缩），自动更新状态文件超过 64 KB 不打包；压缩后超过 **20 MB** 不会发送
- 服务端：建议拒绝超过 20 MB 的请求体并返回 `413`

### 超时与重试

- 单次请求超时 20 秒
- 网络错误、超时、`5xx`、`408`、`429` 时重试 1 次（间隔 1 秒）；其他 `4xx` 不重试

## 响应

成功时返回 `2xx` 与 JSON：

```json
{ "ok": true, "ticketId": "LOG-20261006-0001" }
```

- `ok` 必须为 `true`，否则客户端视为失败
- `ticketId` 可选：会在关于窗口显示为「日志已上传（编号 xxx）」，方便用户在反馈时引用

失败时返回非 `2xx`（响应体可以是 `{ "ok": false, "error": "..." }`，客户端只看状态码）。

## zip 内容

| 路径                             | 内容                                                                                                                                                                                                                                                                                                                        |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `diagnostics.json`               | 上传原因；应用名称 / 版本 / 发布通道 / 是否安装包 / 语言；更新通道、金丝雀计划、灰度分桶与比例；设备 ID；操作系统、架构、内核版本、内存与 CPU 数；Electron / Chromium / Node / V8 版本；首次运行时间、本次启动时间与运行时长、时区；数据目录（userData / 日志 / 示例项目 / 崩溃日志）；本包的文件清单、被截断与被跳过的文件 |
| `crash.json`                     | 仅 `crash`：崩溃类型（`uncaughtException` / `unhandledRejection` / `render-process-gone` / `child-process-gone`）、错误信息、堆栈、退出原因与退出码                                                                                                                                                                         |
| `logs/*.log`                     | electron-log 日志目录（默认 `app.getPath('logs')`）下的 `.log` 文件，最近修改的优先                                                                                                                                                                                                                                         |
| `state/updater-state.json`       | 自动更新状态（通道、灰度分桶、版本指针、回滚目标），用于排查更新 / 回退问题                                                                                                                                                                                                                                                 |
| `state/log-upload-settings.json` | 「崩溃时自动上传日志」开关                                                                                                                                                                                                                                                                                                  |

## 隐私

- 白名单打包：只包含上表中的文件，**不会**包含作品正文、资料文件、SQLite 数据库（`.db` / `.sqlite` 等）或 AI Key
- 所有文本中的用户主目录都被替换成 `~`（同时处理 `/`、`\` 与 JSON 转义后的 Windows 路径），避免泄露系统用户名
- 设备 ID 是随机生成的 UUID，不包含硬件信息或个人信息
- 服务端应只保存排障所需的时间（建议 90 天内自动删除），不得用于其他用途

## 客户端行为

### 手动上传（关于窗口「上传日志」）

1. 主进程打包日志
2. 已配置地址：上传；成功时显示「日志已上传（编号 xxx）」
3. 未配置地址或上传失败：把 zip 保存到系统「下载」目录，文件名 `novel-editor-logs-<yyyyMMdd-HHmmss>-<设备 ID 前 8 位>.zip`，并在访达 / 资源管理器中定位，显示「日志已打包到 下载/xxx.zip，可发送给我们」（上传失败时附带失败原因）

### 崩溃时自动上传

- 触发：主进程 `uncaughtException` / `unhandledRejection`、渲染进程退出（`render-process-gone`，原因不是 `clean-exit`）、子进程异常退出（`child-process-gone`，原因不是 `clean-exit` / `killed`）
- 10 分钟内最多处理一次；处理过程中的错误全部吞掉，不会因为处理崩溃再次崩溃
- 只有「配置了地址」且设置中心「通用 → 更新与诊断 → 崩溃时自动上传日志」开启（默认开启）时才上传
- 未上传（未配置、开关关闭或上传失败）时只把日志包保存到 `userData/crash-reports/`，最多保留 5 个，不会写入「下载」目录
- E2E / 烟雾测试模式下不安装崩溃钩子；E2E 中「下载」目录被重定向到测试 userData 下的 `downloads/`，且不会弹出文件管理器
