# 跨平台验证边界

## 自动门禁

`CI` 工作流的 `required` 是汇总门禁：quality 与全部 native 矩阵项成功才通过；失败、取消、前置任务失败导致的跳过都不能得到成功状态。仓库管理员可将 `CI / required` 设为分支保护必需检查（工作流文件本身不会修改仓库保护设置）。

| 检查                                     | 执行环境                                                                                                                       | 证据                                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| lint / typecheck / 全部 UT               | Ubuntu 24.04 x64                                                                                                               | `unit-test-results` 中 JUnit 和覆盖率                                                                                    |
| 真实文件系统、进程锁、恢复协议、路径授权 | Ubuntu 24.04 x64、macOS 15 Intel 与 ARM64、Windows 2025 x64 与 Windows 11 ARM64                                                | 各 `native-<runner>-<arch>` 的 `native.xml`                                                                              |
| POSIX guardian 中断与恢复                | 上述 Linux / macOS runner                                                                                                      | 实际 `/bin/sh` 子进程；Windows 明确跳过 POSIX 用例                                                                       |
| Windows guardian                         | 上述 Windows runner                                                                                                            | 系统 Windows PowerShell 解析脚本；真实子进程验证健康 ACK、杀死持锁进程后的释放、损坏安装包拒绝与不重放；其他系统明确跳过 |
| 构建体积及静态依赖边界                   | 全部 native runner                                                                                                             | `bundle-*.json`（包含预算报告）                                                                                          |
| Electron GUI 与打包启动                  | Linux 全部离线 E2E；其余平台 GUI 启动、编辑自动保存、文件操作、GUI/CLI 共享日志与会话、灵感、Markdown/公式、原生关闭和打包启动 | `e2e.xml` 与失败日志 / 截图                                                                                              |
| 发布安装包启动                           | Release 每个发行架构                                                                                                           | Windows ARM64 在原生 ARM runner 验证，macOS x64 在 Intel runner；Windows 安装 NSIS 后再检查快捷方式目标的健康启动        |

每个 native job 只构建一次，目录打包和 E2E 共用该产物；E2E 显式跳过再次构建。找不到打包可执行文件、未在时限内健康退出、非零退出都会使任务失败。PR 不导入证书、不发布产物；macOS 无证书包不代表正式签名权限验收。检查报告在 `always()` 上传，保留 7 天；每个 job 有明确超时，矩阵 `fail-fast: false` 保留其他平台诊断。

runner 标签与架构已于 2026-10-09 按 [GitHub 官方 runner 列表](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) 核对。公开仓库可使用这些标准 runner；私有仓库遵循账号分钟数与计费额度。托管 macOS ARM runner 没有固定 UDID，Windows runner 以管理员运行且关闭 UAC，因此不能用这些测试证明标准用户、企业策略或提权交互行为。

## 工作区锁的实际边界

租约声明全部相关路径，并同时覆盖路径别名与解析后的真实路径；祖先/子目录相互冲突。不同工作区且没有共享数据库或路径的任务可以并行。CLI 的已知内置命令声明输入、输出及写作日志范围；未知扩展命令和无法提前确定路径的文件对话框仍使用保守的全局租约。旧格式锁票据按全局范围读取，遇到存活的旧进程不会强行接管。

GUI 在异步解析资源前登记调用顺序，重叠写任务按顺序进入原有文件队列，导出等快照等待在先写任务全部完成。数据库初始化、切换和关闭使用独占屏障；排队操作在执行前再次检查数据库身份，避免向已切换的连接写入。

返回任务 ID 的版本快照使用独立后台租约，覆盖扫描和最终落库；状态查询只读内存，不等待任务持有的租约。视频前台操作和后台下载共用完整资源声明，取消操作能中止尚未结束的网络下载；真实门禁回归测试覆盖这两个生命周期。

文本 AI 和连接测试只在读取配置/凭据时持短租约，等待网络返回时释放。图片、语音和视频任务包含落盘或数据库状态变更，仍可能在较长操作中持有对应作品及数据库的租约；共享同一数据库的跨进程操作或快照会相互等待，这是保护一致性的取舍，并不承诺同库任务无等待。单进程写任务继续使用既有队列，不把写入串行策略替换为任意并发。外部编辑器、其他 OS 用户和网络文件系统不参与这套协作协议。

## 必须在设备上验收

托管虚拟机的绿灯不能证明 Touch ID、Windows Hello 或外置安全钥匙登录成功。当前产品也尚无账号服务与登录界面；完整注册 / 登录仍需后端集成。

- macOS：使用合法匹配 profile、真实签名和公证的产物，在已录入指纹的 Touch ID 设备上检查 `touchIdConfigured` / `touchIdAvailable`，再完成注册、登录、取消、指纹失败与设备锁定后的恢复。默认无 profile 的证书包应正常启动且 Touch ID unavailable。细节见 [Passkey 接入](passkey-auth.md)。
- Windows：在启用 Windows Hello 的标准用户设备上完成平台凭据注册 / 登录、PIN 或生物识别取消与失败；另测受组策略限制的 PowerShell、实际 UAC 授权/取消、安装权限不足和目标文件被占用。
- 更新恢复：真实旧版→新版安装、中途强退、重启后登录恢复、旧版健康 ACK，以及安装授权失败后的提示，须在各 OS 的真实安装产物上验收。Windows guardian CI 不执行伪造安装器，也不证明 NSIS 完整回退；Linux Debian 系统授权提示与 macOS profile/AMFI 信任同样不由 mock 证明。

可在受控、人工启动的专用 self-hosted 设备执行上述步骤。不要让外部 PR 自动调度持有证书、profile、凭据或个人作品的设备；本次没有新增此类远程执行入口。
